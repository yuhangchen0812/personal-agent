# 全局审查与改进

日期：2026-11-03。审查起点：[初始公开提交 1c9bd90](https://github.com/yuhangchen0812/personal-agent/commit/1c9bd900652eb8e250b875ffcef2de48303f7ee5)。

本轮检查运行入口、Agent Loop、工具权限、工作区、会话/恢复、协议、CI 应用、验证器、文档和 GitHub 工作流。修改前全量 unittest discovery 的 208 项测试通过；随后通过单独复现补充了现有测试未覆盖的行为。

## 已修复的问题

| 问题 | 复现与影响 | 改进 |
| --- | --- | --- |
| 并发读取丢失工作区上下文 | tool_workspace 指向临时工程时，串行可读，并发会回落到默认工程；同名文件可能读错 | 每个读取任务使用独立的 copy_context，继承调用者工作区和请求上下文 |
| 不合法的工具响应被当成普通回答 | tool_calls={}、False、0 等假值被 or [] 掩盖；空白 ID 与 Session 校验规则不一致 | 在追加响应或执行工具前检查真实列表类型及去空白后的 ID |
| 公开版默认验收依赖私人历史 | 本地组通过后，缺失未分发的历史 JSON 仍会使总结果失败 | 离线默认验收不读取历史；--history 显式启用且保持严格失败条件 |
| CI 未覆盖关键核心回归 | 既有分组没有运行 test_agent.py 等核心单元测试，新发现的问题可漏检 | 增加 core_unit 组，覆盖循环、工具、权限、Session、Plan、配置和验收器 |
| 容器触发条件缺少构建输入 | Dockerfile 复制 examples 和 playground/README.md，但仅修改这些文件不会触发容器工作流 | 将对应输入加入 push / pull_request 路径过滤 |

Windows CI 改用本地同一总控，减少重复编排，并保留总结果、逐组日志及源码指纹。源码指纹检查也覆盖所有工作流文件。公开文档根据实际远端报告更新容器验证范围，初始演示摘要新增对应提交引用，未重写旧测量数据。

## 新增回归

- 并发实际读取两个隔离工作区文件，不能返回外层工程的同名内容。
- 非法 tool_calls 容器不改变历史、不执行工具。
- 空白工具调用 ID 在执行前被拒绝。
- 默认验收不读取私人历史文件，结果仍能通过。
- 显式历史检查缺失/失败时继续拦截，不能把本地通过扩大成完整证据通过。

本轮没有引入新依赖，没有新增远端模型请求，也没有改变权限审批、候选显式采纳或会话恢复不重放旧工具的原则。

## 验证口径

最新实际结果见 [VALIDATION.md](VALIDATION.md)。全量 unittest 与默认分组有共用流程，不将两种计数相加作为覆盖率，也不据固定响应得出模型质量结论。

本次是有范围的工程审查和回归验证，不是完整形式化证明或操作系统沙箱审计。原生 Anthropic 远端签名、其他部署目标和更广泛的真实任务质量仍需独立证据。
